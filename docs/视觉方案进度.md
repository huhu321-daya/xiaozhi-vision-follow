# 小智 AI 视觉方案 —— 进度记录

> 目的：防止对话过长忘记进度。视觉跟随一共迭代了三个阶段：**小脑控制 → 小脑+大脑协作 → 电脑端大脑**，最终收敛到「电脑端大脑」方案。

---

## 一、总体架构（已定）

```
小脑（本地 · 快 · 免费）  发送端 AAS3-CAM 本地跑人体检测 → 跟随/停车，延迟 <0.5s
大脑（云端 · 慢 · 聪明）  拍照 → VLM 理解("去门那边") → 下指令，延迟 2~5s
```

分工：**小脑开车，大脑指路**。大模型绝不每帧控制电机。

---

## 一·五、实验阶段演进总览（三阶段）

视觉跟随从「ESP32 本地检测」一路演进到「电脑端大脑」，共三个阶段：

| 阶段 | 方案 | 决策位置 | 结果 | 演进原因 |
|---|---|---|---|---|
| ① 小脑控制 | 发送板本地跑人体检测 `PedestrianDetect` | ESP32 发送板 | 延迟低（~300ms），但精度有限、易误检 | 单独小脑不够聪明 |
| ② 小脑+大脑协作 | 小脑本地检测 + 云端 `Qwen3-VL` 低频校准 | ESP32 + 云端 VLM | 云端能纠错，但延迟 1.3~2s、仍跑偏 | 云端太慢、ESP32 算力不足 |
| ③ 电脑端大脑 | 电脑跑 YOLOv8n 检测+决策，ESP32 只推流+执行 | 电脑端 | 精度高、决策灵活、好调参 | 当前最终方案 |

### 三阶段一句话

1. **小脑控制**：发送板本地跑 `PedestrianDetect` 行人检测（435KB 模型、~125ms 推理），检测到人就通过 UDP 广播 `FOLLOW` 给接收板跟随。
2. **小脑+大脑协作**：小脑保实时（300ms），云端硅基流动 `Qwen3-VL-8B` 每 2.5s 抓帧校准（纠误检、估距离），两边融合决策。
3. **电脑端大脑**：电脑拉发送板 MJPEG 流跑 YOLOv8n，按「近→前进、偏→转向、远→后退」决策，UDP 广播 `MOTOR` 给接收板，ESP32 双板只做推流和执行。

> 每个阶段的详细实现、代码位置、踩坑记录见下文「阶段 1 / 阶段 2 / 阶段 3」各章节。

## 三、阶段 1：小脑（人体检测替换帧差）✅ 已完成

### 实现方式

- 依赖：`espressif/pedestrian_detect: "0.3.3"`（内部自动带 esp-dl，无需手动加 esp-dl 组件）
- 模型：`PedestrianDetect::PICO_S8_V1`（行人专检，435KB，ESP32-S3 推理 ~125ms，与 1s 检测间隔匹配）
- 新增桥接层：`aas3cam_node/main/cam_detect.h`（C 接口）+ `cam_detect.cpp`（C++ 封装）
- `cam_camera.c` 改动：
  - 删除帧差逻辑（GRID_W/GRID_H、follow_update、prev 数组）
  - JPEG 解码缩放 1/2 → `cam_detect_run(rgb, w, h, &has, &zone, &dist)`
  - 初始化阶段调 `cam_detect_init()`
- 结果映射：框中心 x → zone（L/C/R），框面积 → dist（1/2/3），有框 → has=1
- UDP 协议 `FOLLOW <has> <zone> <dist>` 完全不变，接收端零改动

### 编译/烧录结果

- bin 大小 2.68MB，factory 分区 4MB 剩余 33%，无空间压力
- 烧录 COM4 成功，运行日志确认 `detect: pedestrian model ready`
- 内存：8MB PSRAM + 235KB 内部 SRAM，充足

### 验证状态

- ✅ 无人静止：`FOLLOW has=0 zone=C dist=0`（当前画面无人）
- ⏳ 有人跟随：需人站摄像头前，看 `person n=... score=... box=...` 日志 + 小车动作

### 验证标准
- 有人就跟随、没人完全静止
- 前后 / 左右方向正确
- 不再把光影/摄像头自身移动误判成目标

## 三·五、阶段 2：大脑（看图说话 + 跟随云端辅助）✅ 已完成

### 2.1 视觉模型确定（替代原智谱方案）

- 智谱 `glm-4v-flash` 报 **429 余额不足** → 切换硅基流动 **`Qwen/Qwen3-VL-8B-Instruct`**（免费、OpenAI 兼容、国内直连）
- API：`https://api.siliconflow.cn/v1/chat/completions`，Key 已在代码中

### 2.2 看图说话链路（拍照问小智"照片里是什么"）

- 链路：语音触发 `camera.describe` → 抓帧 JPEG → base64 → Qwen3-VL → 中文简要描述
- 优化响应速度：提示词限 50 字内 + `max_tokens=200`（原 20s 级/800+ 字 → 秒级/短句）
- 提示词加「用中文」关键词，避免返回英文
- **修复 HTTP 超时**：POST 改用 `SetContent()` 走 Content-Length 固定长度模式（原来仅 `Write()` 进 chunked 模式却没发结束块，服务端一直等）

### 2.3 跟随云端辅助（小脑主控 + 大脑校准）

- 实测纯云端跟随延迟 **1.3~2.0s**，会卡顿 → 定为「**小脑工作、大脑辅助**」：
  - 小脑：本地检测保证实时（300ms），阶段 1 基础上再优化：
    - `CAM_FOLLOW_MS` 1000→**300ms**
    - 置信度阈值 **score≥0.60** 过滤低分误检
    - 连续帧确认计数 `[-2,2]` 防单帧抖动
    - 无人确认时重置 EMA 平滑状态，防止残留旧值
  - 大脑：`CamVlmCalibTask` 跟随开启时每 **2.5s** 抓帧调 Qwen3-VL 做结构化判断
    - 融合逻辑：云端判无人（6s 内有效）→ 否决小脑误检停住；云端距离有效 → 覆盖小脑框高粗估
    - 容错解析 `ParseFollowVlm()`：模型返回 JSON 缺逗号也能直接搜关键词/数字提取字段

### 2.4 验证状态

- ✅ 双板连通（小脑 `receiver online ip=192.168.1.5`）
- ✅ 跟随开启、云端校准周期 2.5s、单次推理 0.5~2s
- ✅ 容错解析生效（`answer={"has":0"zone":"center""dist":1}` 缺逗号仍正确提取）
- ⏳ 需实测：真人跟随是否被云端误否决（云端 has=0 会停 6s），以及海报/屏幕人像误检是否被正确否决

## 三·七、阶段 3：电脑当大脑（外部算力跟随）🔄 进行中

### 3.1 架构调整（为什么换方案）

- 小脑本地检测（帧差/人体检测）+ 云端 VLM 都不理想：延迟高、误检、转向跑偏
- 改为 **电脑当大脑**：所有检测与决策都在电脑端完成，ESP32 只做执行
  - 发送板 AAS3-CAM 只做两件事：**MJPEG 推流 + UDP 电机转发**（关闭本地决策 `FOLLOW_OFF`）
  - 电脑端 `phone_follow/phone_follow.py` 拉流 → YOLOv8n 检测 → 决策 → UDP 广播电机指令
- **车尾背装适配**：摄像头朝后安装，前进/后退动作交换，转向方向适配镜像场景

### 3.2 电脑端脚本（phone_follow.py）

- 检测：`yolov8n.onnx`（cv2.dnn 推理），只取 person 类，置信度 ≥0.25
- 发送板分辨率：OV3660 **VGA(640×480)**，`jpeg_buffer_size=64KB` 解决 FB-OVF 帧溢出
- 拉流：`http://192.168.1.11/stream`，后台线程只保留最新帧（丢旧帧降延迟）
- 决策下发：UDP 广播 `MOTOR <dir> <speed> <dur>` 到 **8093** 端口
- 电机编码：`1=右转 2=后退 3=左转 4=前进`（车尾背装：前进=远离、后退=靠近）

### 3.3 决策逻辑（优先级从高到低）

| 优先级 | 条件 | 动作 |
|---|---|---|
| 1 | 框宽占比 ≥0.80（≈0.5 米内）或贴边 | 前进（远离） |
| 2 | 框中心偏移 >0.12 | 转向对齐（比例转向） |
| 3 | 框宽占比 ≤0.40（≈1.5 米外） | 后退（靠近） |
| 4 | 其余 | 静止 |

- 距离换算：框宽占比与距离近似反比（`w × 距离 ≈ 常数`），按 0.5 / 1 / 1.5 米实测标定
- 贴边检测：`touch = (x1<=2 or x2>=w-2) and w_ratio>0.5`，解决 0.5 米人体超画面误判
- 转向方向：**人偏右→右转(dir=1)、偏左→左转(dir=3)**（车尾镜像已适配）
- 比例转向：`dur = |off| × 66° × 9ms/度`（30~200ms 封顶），偏得多转得多，避免过冲
- 限速发指令：发一条后等 `dur + 0.30s` 再发下一条（接收板每条指令阻塞 dur 毫秒，防止积压）

### 3.4 已修复的 bug

| 问题 | 根因 | 修复 |
|---|---|---|
| 0.5 米人体超画面误判 | 检测框被画面边缘裁剪 | 贴边检测 `touch` |
| 只进退跑偏 | 无转向对齐 | 恢复转向对齐优先级 |
| 扭头约 270 度 | 转向方向反了 | 人偏右转右、偏左转左 |
| 一直扭头不停 | 固定 150ms 转向过冲 + 指令积压 | 比例转向 + 限速发指令 |
| 动作混乱 | 两个脚本实例同时广播 | 杀旧实例单实例运行 |

### 3.5 待验证

- ⏳ 转向对齐是否稳定对准人体、无来回抖动（设备已没电，下次上电验证）
- ⏳ 0.5 米前进 / 1 米静止 / 1.5 米后退 的实际动作表现
